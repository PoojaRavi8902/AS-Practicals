Part C — Short Answers (model answers)

  1. Abstraction: removing unnecessary details so the essential aspects of a problem are modelled.
  2. Benefits of decomposition: easier testing and simpler development; allows parallel work and code reuse.
  3. Pseudocode model: 
    INPUT A,B,C
max ← A
IF B > max THEN max ← B ENDIF
IF C > max THEN max ← C ENDIF
OUTPUT max
  4. Identifier table contains variable names, data types, and purpose/description.
  5. Validation example: check email contains '@' and a domain, and length within limits.
  6. AND : true when both conditions true (e.g., age>=18 AND hasID=true). OR : true when at least one true (e.g., score>=50 OR extraCredit=true).
  7. Stepwise refinement: breaking a high‑level task into more detailed sub‑steps until each is implementable.
  8. Include: clear identifiers, correct control structures (IF/FOR), and indentation/END keywords.
  9. Trace table header example: Step | i | sum | value
  10. Dry‑run can help detect logical errors and off‑by‑one errors (also boundary errors).

RecordAttendance pseudocode (short):

PROCEDURE RecordAttendance(studentID, date, status)
  // assume student exists
  attendanceRecord ← {StudentID: studentID, Date: date, Present: status}
  Append attendanceRecord to AttendanceList

Q2 — Average function (model)

FUNCTION CalculateAverage(scores, n)
  total ← 0
  FOR i ← 0 TO n-1
    total ← total + scores[i]
  NEXT i
  avg ← total / n
  RETURN avg
ENDFUNCTION

Parameter passing: If passed by value, the function receives a copy (original array unchanged unless arrays are reference in language). For exams, state the assumed convention. Test cases: scores=[10,20,30], n=3 → avg=20; scores=[0,0,0], n=3 → avg=0; n=1 edge case.

Q3 — Off‑by‑one (model)

An off‑by‑one error occurs when loop bounds are incorrect (e.g., using <= instead of <). Example:

// Incorrect (off-by-one) for array length N
FOR i ← 0 TO N
  process array[i]
NEXT i
// This accesses array[N] which is out of bounds

// Correct:
FOR i ← 0 TO N-1
  process array[i]
NEXT i

Q4 — Validate & verify taxes program (model)

Validation: Check salary ≥ 0, valid tax year, correct format for ID. Verification: Provide expected outputs for sample inputs and compare. Test data: salary=0, salary=10000, negative salary (invalid), very large salary. Use trace tables for failing cases and log fixes.

Q5 — Linear vs Binary search (model)

Linear search: scan elements from start to end; works on unsorted lists. Pseudocode:

FUNCTION LinearSearch(array, key)
  FOR i ← 0 TO Length(array)-1
    IF array[i] = key THEN
      RETURN i
    ENDIF
  NEXT i
  RETURN -1
ENDFUNCTION

Binary search: halves sorted list each iteration; much faster on large sorted arrays but requires sorted input. Not usable on unsorted lists because the halving property relies on order.
