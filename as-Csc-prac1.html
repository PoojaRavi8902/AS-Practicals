12.01 — What is computational thinking?

Computational thinking is a methodical problem-solving approach where problems are analysed and solutions are created as step-by-step procedures that humans can understand and computers can execute. The key strands are:

  • Abstraction — keep only essential details.
  • Decomposition — split into sub-problems.
  • Data modelling — organise data using types and structures.
  • Pattern recognition — reuse known solutions.
  • Algorithmic thinking — design precise step sequences.
Exam tip

When answering long questions about computational thinking, explicitly name the strand you are using (e.g., "I used abstraction to remove irrelevant details such as exact street positions") and show the effect on the solution.

Abstraction

Abstraction filters out unnecessary information. For example, a London Underground map shows stations and connections — not the exact geographic layout. Abstraction reduces complexity and focuses on what is relevant to the task.

Decomposition & Data modelling

Decomposition breaks a problem into smaller pieces—modules, procedures or functions—each of which is easier to develop and test. Data modelling analyses required data and defines abstract data types such as stacks, queues or classes.

Classroom exercise

Decompose the task "build a student grading system" into modules (input, validation, calculation, storage, reporting). For each module list required inputs and outputs.

Pattern recognition

Recognising patterns lets you apply robust standard algorithms — e.g., sorting and searching algorithms — to similar problems, saving time and reducing errors.

12.02 — What is an algorithm?

An algorithm is a sequence of clear, unambiguous steps for solving a problem. Everyday procedures (changing a wheel, baking a cake) are algorithms: inputs, processes, and outputs.

Wheel-change (sequence) 
1. Loosen wheel nuts
2. Position jack
3. Raise car
4. Remove wheel
5. Fit replacement
6. Lower car and tighten nuts

Order matters — incorrect sequencing can make the task impossible. Algorithms may contain conditional steps (selection) or repeated steps (iteration).

12.03 — Expressing algorithms

Algorithms are expressed in structured English, pseudocode or flowcharts. Key constructs are Assignment, Sequence, Selection and Repetition. Use input/process/output model when designing solutions.

Structured English vs Pseudocode 
Structured English:
SET A to 34
Increment B

Pseudocode:
A ← 34
B ← B + 1

12.06 — Logic statements

Selection uses conditions to choose different steps. Conditions are TRUE or FALSE. Common relational operators: =, <, >, <=, >=, <> (not equal).

Number-guessing (selection) 
SET SecretNumber
INPUT Guess
IF Guess = SecretNumber THEN
   OUTPUT "Well done"
ELSE
   IF Guess > SecretNumber THEN OUTPUT "Secret number is smaller"
   ELSE OUTPUT "Secret number is greater"
   ENDIF
ENDIF

12.07 — Loops & Repetition

Use repetition constructs to repeat tasks: FOR...NEXT, REPEAT...UNTIL, WHILE...ENDWHILE. Choose based on whether count is known or whether loop must execute at least once.

Finding largest of many inputs — using FOR loop 
INPUT BiggestSoFar
FOR Counter ← 2 TO 10
   INPUT NextNumber
   IF NextNumber > BiggestSoFar THEN BiggestSoFar ← NextNumber ENDIF
NEXT Counter
OUTPUT BiggestSoFar
Rogue value termination (0 terminates) 
INPUT BiggestSoFar
REPEAT
   INPUT NextNumber
   IF NextNumber > BiggestSoFar THEN BiggestSoFar ← NextNumber ENDIF
UNTIL NextNumber = 0
OUTPUT BiggestSoFar
Task — Number-guessing with loop

Implement this algorithm on paper using REPEAT...UNTIL and then try a pre-condition WHILE version. Explain which is safer if input may be immediately the terminating value.

12.04 Variables

A variable is a named memory location used to store a data value. You can think of it like a box with a label: the label is the identifier, and the contents of the box are the value.

Key Term: Variable – a storage location for a data value that has an identifier.

Identifiers should not contain spaces. They may use letters, digits and underscores. The CamelCaps convention is commonly used (e.g. NumberOfGuesses, ThisPlayer).

Assignments

An assignment stores a value in a variable. 

INPUT Number
NumberOfGuesses ← 1
NumberOfGuesses ← NumberOfGuesses + 1
Value2 ← Value1

Swapping values

Temp ← Value1
Value1 ← Value2
Value2 ← Temp

12.07 Loops

Repetition constructs allow instructions to be repeated.

Key Term: Rogue Value – a special value used to terminate input.

Worked Example 12.04 – Using REPEAT...UNTIL

INPUT BiggestSoFar
Counter ← 1
REPEAT
    INPUT NextNumber
    Counter ← Counter + 1
    IF NextNumber > BiggestSoFar THEN
        BiggestSoFar ← NextNumber
    ENDIF
UNTIL Counter = 10
OUTPUT BiggestSoFar

Worked Example 12.05 – Using FOR...NEXT

INPUT BiggestSoFar
FOR Counter ← 2 TO 10
    INPUT NextNumber
    IF NextNumber > BiggestSoFar THEN
        BiggestSoFar ← NextNumber
    ENDIF
NEXT Counter
OUTPUT BiggestSoFar

Worked Example 12.06 – Using Rogue Value

INPUT NextNumber
BiggestSoFar ← NextNumber
WHILE NextNumber <> 0 DO
    INPUT NextNumber
    IF NextNumber > BiggestSoFar THEN
        BiggestSoFar ← NextNumber
    ENDIF
ENDWHILE
OUTPUT BiggestSoFar

Worked Example 12.07 – Number Guessing Game

SecretNumber ← Random
NumberOfGuesses ← 0
REPEAT
    INPUT Guess
    NumberOfGuesses ← NumberOfGuesses + 1
    IF Guess = SecretNumber THEN
        OUTPUT "Well done!"
    ELSEIF Guess > SecretNumber THEN
        OUTPUT "Secret number is smaller"
    ELSE
        OUTPUT "Secret number is greater"
    ENDIF
UNTIL Guess = SecretNumber

12.08 Running Totals and Averages

Totals and averages are common algorithms that use accumulation in loops.

Worked Example 12.08 – Sum and Average

IdentifierExplanation
RunningTotalSum of all numbers so far
CounterHow many numbers entered
NextNumberLatest number entered
AverageMean of all numbers entered
RunningTotal ← 0
FOR Counter ← 1 TO 10
    INPUT NextNumber
    RunningTotal ← RunningTotal + NextNumber
NEXT Counter
OUTPUT RunningTotal
Average ← RunningTotal / 10
OUTPUT Average

12.09 Modules

Another method of developing a solution is to decompose the problem into sub-tasks. Each sub-task can be considered a module that is refined separately. Modules are of two kinds: procedures and functions.

Procedure: a sequence of steps grouped together under an identifier, which can be called to perform a sub-task.
Function: a sequence of steps grouped under an identifier, but returns a single value; the function call is part of an expression.

The rules for module identifiers are the same as for variable identifiers (see Section 12.04). Functions also state the data type of the value they return.

Worked Example 12.12 – Drawing a Pyramid using Modules

Top-level solution using procedures and functions:

01   CALL SetValues
02   REPEAT
03       CALL OutputSpaces
04       CALL OutputSymbols
05.1     NumberOfSpaces ← AdjustedNumberOfSpaces
05.2     NumberOfSymbols ← AdjustedNumberOfSymbols
06   UNTIL NumberOfSymbols > MaxNumberOfSymbols

This top-level solution calls four procedures, which are defined below:

PROCEDURE SetValues
    INPUT Symbol
    CALL InputMaxNumberOfSymbols // ensure odd number
    NumberOfSpaces ← (MaxNumberOfSymbols - 1) / 2
    NumberOfSymbols ← 1
ENDPROCEDURE

PROCEDURE InputMaxNumberOfSymbols
    REPEAT
        INPUT MaxNumberOfSymbols
    UNTIL MaxNumberOfSymbols MOD 2 = 1
ENDPROCEDURE

PROCEDURE OutputSpaces
    FOR Count1 ← 1 TO NumberOfSpaces
        OUTPUT Space // stay on same line
    NEXT Count1
ENDPROCEDURE

PROCEDURE OutputSymbols
    FOR Count2 ← 1 TO NumberOfSymbols
        OUTPUT Symbol // stay on same line
    NEXT Count2
    OUTPUT Newline
ENDPROCEDURE

PROCEDURE AdjustValuesForNextRow
    NumberOfSpaces ← NumberOfSpaces – 1
    NumberOfSymbols ← NumberOfSymbols + 2
ENDPROCEDURE

One benefit of using modules is reusability. To maximize this, modules should be self-contained, using parameters instead of relying on external variables.

Worked Example 12.13 – Pyramid with Parameters

REPEAT
    CALL SetValues(Symbol, MaxNumberOfSymbols, NumberOfSpaces, NumberOfSymbols)
    CALL OutputSpaces(NumberOfSpaces)
    CALL OutputSymbols(NumberOfSymbols, Symbol)
    NumberOfSpaces ← AdjustedNumberOfSpaces(NumberOfSpaces)
    NumberOfSymbols ← AdjustedNumberOfSymbols(NumberOfSymbols)
UNTIL NumberOfSymbols > MaxNumberOfSymbols

Definitions of modules with parameters:

PROCEDURE SetValues(Symbol, MaxNumberOfSymbols, NumberOfSpaces, NumberOfSymbols)
    INPUT Symbol
    MaxNumberOfSymbols ← ValidatedMaxNumberOfSymbols
    NumberOfSpaces ← (MaxNumberOfSymbols - 1) / 2
    NumberOfSymbols ← 1
ENDPROCEDURE

FUNCTION ValidatedMaxNumberOfSymbols RETURNS INTEGER
    REPEAT
        INPUT MaxNumberOfSymbols
    UNTIL MaxNumberOfSymbols MOD 2 = 1
    RETURN MaxNumberOfSymbols
ENDFUNCTION

PROCEDURE OutputSpaces(NumberOfSpaces)
    FOR Count1 ← 1 TO NumberOfSpaces
        OUTPUT Space
    NEXT Count1
ENDPROCEDURE

PROCEDURE OutputSymbols(NumberOfSymbols, Symbol)
    FOR Count2 ← 1 TO NumberOfSymbols
        OUTPUT Symbol
    NEXT Count2
    OUTPUT Newline
ENDPROCEDURE

FUNCTION AdjustedNumberOfSpaces(NumberOfSpaces) RETURNS INTEGER
    NumberOfSpaces ← NumberOfSpaces – 1
    RETURN NumberOfSpaces
ENDFUNCTION

FUNCTION AdjustedNumberOfSymbols(NumberOfSymbols) RETURNS INTEGER
    NumberOfSymbols ← NumberOfSymbols + 2
    RETURN NumberOfSymbols
ENDFUNCTION
Local Variable: accessible only within its module.
Global Variable: accessible from all modules.
Good design prefers local variables, making modules independent and reusable.

Summary

  • Abstraction filters out unnecessary detail.
  • Decomposition breaks problems into sub-problems (modules).
  • An algorithm is a sequence of steps expressed with assignment, sequence, selection, repetition.
  • Pseudocode is used to document algorithms.
  • Logic statements use relational (=, <, >, <>, <=, >=) and logical (AND, OR, NOT) operators.
  • Selection constructs and conditional loops depend on conditions.
  • Stepwise refinement breaks down outline solutions into finer steps.

Question 1 – Modulo-11 Check Digit [9]

Write pseudocode to calculate a Modulo-11 check digit from a 9-digit sequence as per the flowchart.

Suggested Answer 
Weighting ← 10
Total ← 0
FOR Count ← 1 TO 9
    INPUT Digit
    Value ← Digit * Weighting
    Total ← Total + Value
    Weighting ← Weighting - 1
NEXT Count
Remainder ← Total MOD 11
CheckDigit ← 11 - Remainder
IF CheckDigit = 10 THEN
    CheckDigit ← "X"
ENDIF
OUTPUT CheckDigit

Question 3 – Average with Rogue Value [7–8]

Suggested Answer

Total ← 0
Count ← 0

WHILE Number <> RogueValue DO
