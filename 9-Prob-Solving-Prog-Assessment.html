Part C — Short Answers (model answers)

  1. Top‑down design: Start with a high‑level specification and iteratively break it into smaller modules until each is implementable.
  2. Procedure vs Function: (1) Function returns a value; procedure may not. (2) Function is used in expressions; procedure is usually called for side effects.
  3. Pseudocode (swap via reference): 
    PROCEDURE Swap(&a, &b)
  temp ← a
  a ← b
  b ← temp
ENDPROCEDURE
  4. Global scope: Visible throughout the program in all modules.
  5. Records group related fields so code is clearer and less error-prone than parallel arrays.
  6. Module documentation: Purpose, parameters, return values (and side effects).
  7. Off‑by‑one: A loop boundary error where the loop iterates one time too many or too few (e.g., using <= N instead of < N).
  8. Linear search scans sequentially; binary search divides sorted list and is faster on sorted data.
  9. Function header example: FUNCTION CalculateSum(Array, N) RETURNS sum
  10. Test cases for login: valid credentials; invalid password; missing username; SQL injection attempt (exceptional).

Part D — Long Answers (model solutions)

Q1 — Library system (model)

Module list: Main(), LoadBooks(), LoadMembers(), IssueBook(), ReturnBook(), SearchCatalogue(), SaveData().

IssueBook pseudocode:

PROCEDURE IssueBook(memberID, bookID)
  IF NOT MemberExists(memberID) THEN
    OUTPUT "Invalid member"
    RETURN
  ENDIF
  IF BookAvailable(bookID) THEN
    MarkBookAsIssued(bookID, memberID)
    OUTPUT "Issued"
  ELSE
    OUTPUT "Not available"
  ENDIF
ENDPROCEDURE

Identifier table (sample): memberID:String, bookID:String, issueDate:Date, dueDate:Date

Q2 — Median of odd-length array (model)

High-level: Sort array (or use selection algorithm), pick middle element. Pseudocode (simple):

FUNCTION Median(array, n)
  Sort(array)
  mid ← n DIV 2
  RETURN array[mid]
ENDFUNCTION

Test cases: [1,3,2] -> after sort [1,2,3] mid=1 -> 2. Edge: n=1 -> return sole element.

Q3 — Boundary testing when N=0 (model)

Include test cases: N=0 (expect error or empty result), N=1 (boundary), normal N. Trace failing run for N=0 showing where algorithm assumes non-zero and causes division by zero or index error.

Q4 — Highest mark in array of records (model)

FUNCTION FindTopStudent(students, n)
  topIndex ← 0
  FOR i ← 1 TO n-1
    IF students[i].Mark > students[topIndex].Mark THEN
      topIndex ← i
    ENDIF
  NEXT i
  RETURN students[topIndex].ID
ENDFUNCTION

Identifier table: students:Array of Record Student{ID,Name,Mark}, n:Integer, topIndex:Integer. Traversal: linear scan is appropriate once; efficient and simple.

Q5 — Pass‑by‑reference vs pass‑by‑value for large arrays (model)

Pass‑by‑reference avoids copying large arrays (fast, memory efficient) but risks side effects; pass‑by‑value is safe (no side effects) but costly for large data. Recommendation: use pass‑by‑reference with careful documentation or pass indices/handles to avoid full copies.
